Guardrail policy

Changes apply to the next agent turn — no restart. The engine is rebuilt per run, so a case already mid-flight finishes under the policy it started with.

These are not general settings. Each one decides something the agent may or may not do to a customer, and the agent is told when a rule refuses it — the refusal, its reason and a workable alternative go back into the next turn's briefing, so tightening a rule changes what the agent chooses rather than only what it is prevented from doing.

changed here means an operator set it on this screen and it overrides the environment; from .env means the deployment set it; default is the value the code ships with. Every refusal is written to the guardrail audit log with the agent version that was running.
